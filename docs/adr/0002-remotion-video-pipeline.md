# Remotion as an alternative video generation pipeline for Distorama slideshows

The weekly Distorama YouTube Short is produced by a second pipeline (`scripts/toulouse-distorama/remotion/`) built on Remotion rather than Playwright browser capture. Both pipelines coexist: the original `capture-slideshow.js` (Playwright + ffmpeg) remains the reference; the Remotion pipeline is the preferred path going forward.

The Playwright approach records a live headless browser session running the Hugo slideshow, then post-processes audio with a hand-written ffmpeg filter graph. This works but has two pain points: timing drift between the browser recording and the audio composite (requiring the `--remix` workaround and a CSV timestamp log to realign them), and fragility in the ffmpeg filter graph (one failed yt-dlp download can corrupt the audio mix). Remotion renders frame-by-frame from a React composition, so audio and video are aligned by construction — no timestamp log, no remix mode, no filter graph.

The Remotion composition uses MapLibre GL JS (not Mapbox GL JS) with the MapTiler Toner-v2 style. The Hugo slideshow keeps Mapbox GL JS unchanged. The two pipelines produce visually distinct outputs: the Remotion video is a new design purpose-built for 1080×1920 vertical video (split screen: MapLibre map top half, YouTube video clip bottom half, venue card overlay), not a port of the Hugo slideshow layout. This divergence is intentional — the web and video formats have different constraints.

Map camera position is interpolated per frame via `useCurrentFrame` and `map.jumpTo()`, giving smooth continuous movement between venue positions across slide boundaries. Event cards and video clips fade in/out at slide boundaries via `volume` and `opacity` interpolation. Duration is computed dynamically by `calculateMetadata`, which reads the weekly GeoJSON and counts slides with a `youtube_video_id`. Downloaded YouTube clips are passed as `file://` absolute paths in a `mediaMap` input prop — no symlinks into Remotion's `public/` folder. The ffmpeg audio graph is replaced entirely by `<OffthreadVideo>` and `<Audio>` components inside `<Sequence>` blocks.
