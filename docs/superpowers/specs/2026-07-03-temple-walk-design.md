# Temple Walk Generator — Design

**Date:** 2026-07-03
**Status:** approved

## Overview

A CLI script that generates a self-guided temple walk from any starting point: it finds
the nearest named Buddhist temple via the Overpass API (OSM), walks there via OSRM foot
routing, then greedily chains to the nearest unvisited temple, stopping before the
cumulative walking distance exceeds a configurable budget (default 10 km). Output is a
`walk.geojson` in the bangkok-citywalk schema plus a Hugo map page — one page per walk.

Based on the `bangkok-citywalk` pipeline (`scripts/bangkok-citywalk/generate.py`), but a
separate, city-agnostic script: the Bangkok walk stays curated; this one is generated.

## CLI

```
uv run scripts/temple-walk/generate.py --start "13.7516,100.4927" --slug rattanakosin
uv run scripts/temple-walk/generate.py --start "Democracy Monument, Bangkok" --slug democracy --max-km 8
```

- `--start` (required): `"lat,lng"` if it parses as two floats; otherwise an address
  geocoded via Nominatim (same headers/User-Agent pattern as bangkok-citywalk).
- `--slug` (required): identifier used in all output paths.
- `--max-km` (default `10`): walking-distance budget in kilometres.
- `--dry-run`: print planned actions without network calls or writes.

---

## Pipeline

Each phase caches its result in `scripts/temple-walk/cache/<slug>.*.json` for fast re-runs.

### Phase 1 — Resolve start
Parse `--start` as `lat,lng`; on failure, geocode via Nominatim. Abort with a clear
message if geocoding returns nothing.

### Phase 2 — Discover temples (one Overpass query)
Single query for all candidate temples within the walk budget radius of the start
(a temple farther than the total budget can never be reached):

```
nwr[amenity=place_of_worship][religion=buddhist][name](around:<max_km*1000>,<lat>,<lng>);
out center;
```

- **Named only:** elements without a `name` tag are excluded (labels, photo search, and
  meaningful stops all need a name).
- Ways/relations use their `center` coordinate.
- **Dedupe by name:** when the same temple appears as both a node and a way/relation,
  keep the way/relation.

### Phase 3 — Greedy chain with OSRM legs

```
current = start; total = 0; stops = []; route = []
loop:
  candidate = nearest unvisited temple to current (haversine)
  if no candidate: stop
  leg = OSRM /route/v1/foot/ current → candidate
  if total + leg.distance_km > max_km: stop
  stops.append(candidate); route.append(leg); total += leg.distance_km
  current = candidate
```

- Haversine picks the candidate; OSRM's real walking distance gates acceptance.
- If a leg is rejected, the walk ends — no farther-candidate retries (a farther temple
  implies an even longer leg).
- 1 s sleep between OSRM calls (public `router.project-osrm.org`, same as bangkok-citywalk).

### Phase 4 — Wikimedia photos
Same logic as bangkok-citywalk: Commons search by temple name, download best matches to
`static/temple-walks/<slug>/photos/`, record attribution. Photo failures are non-fatal —
the stop gets an empty `photos` array.

## Output: `static/temple-walks/<slug>/walk.geojson`

Same `FeatureCollection` schema as bangkok-citywalk (compatible with existing tooling):

- One `Point` per temple stop — properties: `name`, `order` (1-based), `photos`
  (local paths), `attribution`, plus new additive fields `osm_id` and `distance_km`
  (cumulative walking distance at that stop).
- One `Point` for the starting point — `order: 0`, `name: "Start"`.
- One `LineString` for the full stitched route — properties: `segment_breaks`
  (coordinate index where each leg starts) and `total_km`.

## Hugo page

- `layouts/temple-walk/list.html`, adapted from `layouts/bangkok-citywalk/list.html`:
  MapLibre GL map, numbered circle markers, dashed orange route line, click-popup with
  temple name + photo. Two changes:
  1. GeoJSON URL read from the page's `geojson` front-matter param (not hardcoded).
  2. The `order: 0` start point rendered as a distinct green marker.
- `content/temple-walks/<slug>/_index.md`, generated by the script:

  ```yaml
  ---
  title: "Temple Walk — <slug>"
  description: "<N> temples, <X> km walking from <start>"
  type: "temple-walk"
  geojson: "/temple-walks/<slug>/walk.geojson"
  ---
  ```

  If the file already exists, the script preserves it (user may have edited title or
  description) and only regenerates the GeoJSON and photos.

## Error handling

- Overpass / OSRM / Nominatim failures: retry once, then abort printing the failing URL.
- Zero temples within the radius, or the first temple already beyond budget: exit with a
  clear message, no output written.
- A short walk (1–2 temples) is valid output: warn and generate anyway.
- Photo failures: warn and continue (empty `photos` array).

---

## Testing

- Pure logic — haversine, greedy selection, budget gate, name-dedupe, GeoJSON assembly —
  lives in plain functions (data in / data out), testable without network.
- Verification run: generate a walk starting near the Grand Palace
  (`--start "13.7516,100.4927" --slug rattanakosin`) and inspect the map page with
  `hugo server`.
- No automated network tests (consistent with the rest of the repo).

---

## Out of scope

- Remotion video for temple walks (the GeoJSON is schema-compatible; can be wired later).
- Route optimisation (TSP / lookahead) — pure greedy nearest-neighbour only.
- Loop walks returning to the start.
- Non-Buddhist places of worship / `--religion` flag.
- CI automation or scheduled regeneration.
